How it works

Four hops to safety

No servers. No towers. Just phones relaying messages through a self-assembling network.

1📱

Send an SOS

Phone A — with no internet or cell — fires an encrypted SOS packet over Bluetooth LE.

2🔗

Mesh relay

Nearby phones running MeshRoute automatically pick up and forward the packet, extending range hop by hop.

3🌐

Gateway upload

The first phone with internet acts as a gateway, uploading via the Nostr relay bridge to the backend.

4🔔

Alert delivered

Your emergency contact receives a real-time notification — even if you're kilometers off-grid.

Features

Built for the edge

Every feature designed for the moments when reliable infrastructure isn't an option.

📡

Zero infrastructure

Operates entirely over Bluetooth LE. No Wi-Fi, no cell towers, no routers. Pure peer-to-peer mesh topology.

🔐

Noise protocol encryption

Every message is E2E encrypted using the Noise Protocol Framework — the same cryptographic foundation as Signal.

♻️

Self-healing topology

Nodes join and leave dynamically. The network reroutes around failures automatically — no single point of failure.

🔋

Power-optimized BLE

Intelligent duty-cycling keeps background drain minimal — hours of relay operation per charge.

⬡

Nostr gateway bridge

When a gateway phone finds internet, messages relay through the decentralized Nostr network — no proprietary server.

📦

Persistent message store

Room database queues messages locally. Nothing is lost during gaps — delivery guaranteed once a path exists.

FAQ

Common questions

How do I install the APK on my Android phone?
+
Download the APK, then tap the downloaded file. When prompted, tap Settings → Allow from this source to enable installation for your browser. Android 8.0+ prompts per-app — tap Install, and MeshRoute is ready to use in seconds.
Does it need Bluetooth and location permissions?
+
Yes — BLE scanning on Android requires location permission (an Android OS requirement). We also request Nearby Devices on Android 12+. We never transmit your GPS without an explicit SOS trigger.
How far can a message travel across the mesh?
+
Each hop covers ~50–100m. There is no limit to hops — as long as there's a chain of MeshRoute devices between sender and gateway, the message will be delivered.
Is the message content encrypted?
+
Yes. All payloads are encrypted using the Noise Protocol Framework (XX handshake). Even relay nodes only forward encrypted bytes — they cannot read content.
What happens if there's no gateway phone with internet?
+
Messages are persisted in a local Room database on every relay node. As soon as any node gains internet, queued messages upload automatically. Nothing is ever lost.
Is this open source? Can I contribute?
+
Yes — full source at github.com/puneetpathak-arch/mesh_network. Issues and PRs welcome. Roadmap includes iOS BLE support and a LoRa radio bridge for even longer range.
